## 1. 이 조사가 시작된 계기 (도입 스토리로 쓰기 좋음)

> 빔 캡쳐를 보정 프로그램에 넣었더니 **회절한계의 9.8배**라는 결과가 나왔다.
> NA 1.42 대물렌즈가 이 정도라면 사실상 작동하지 않는다는 뜻이다.
> "빔이 망가진 건가? 대물렌즈가 문제인가?"

추적 결과, **빔이 아니라 파일이 문제였습니다.** 그리고 그 과정에서 서로 독립적인 함정이 여러 개 드러났습니다.

진단이 두 번 정정된 과정 자체가 좋은 교훈입니다:

```
1차 진단:  회절한계 9.8배  →  "입사빔이 1.03 mm, 후면동공(9.47 mm)을 심하게 underfill"
2차 정정:  스케일 3배 오류 발견  →  실제 2.06배  →  underfill 가설 대폭 축소
3차 정정:  감마 γ≈2.23 발견  →  실제 1.22–1.50배  →  "대물렌즈는 거의 회절한계에서 작동 중"
```

**교훈:** 스케일이 틀리면 진단의 *결론 자체*가 뒤집힙니다. "빔이 망가졌다"와 "빔은 멀쩡하다" 사이를 오갔습니다.

### P1. Dichroic mirror가 수차를 지배한다 ⭐ (가장 의외인 항목)

**[문제]**
같은 대물렌즈, 같은 레이저, 같은 카메라인데 **dichroic만 바꿨더니 초점 스팟의 수차 종류가 바뀌었습니다.**

| | 600 DMSP | 950 DMSP |
|---|---|---|
| 코어 구조 | **bilobed** (두 개의 로브) | 단일 로브 |
| FWHM 종횡비 | 1.14 | **1.82** (강한 astigmatism) |
| 수차 성격 | coma / trefoil 계열 | 순수 astigmatism |

빔이 원인이라면 dichroic 교체와 무관하게 같은 모양이 나와야 합니다. 바뀌었다는 것은 dichroic이 원인이라는 직접 증거입니다.

**[왜 놓치기 쉬운가]**
Dichroic은 "파장을 나누는 부품"으로만 생각하고 **파면(wavefront) 품질**을 따지지 않습니다. 형광 필터큐브에 들어가는 dichroic은 보통 이미징 품질 스펙이 없거나 느슨합니다.

**[물리적 근거 — 슬라이드에 꼭 넣을 것]**

DMSP(shortpass) dichroic에서 **1064 nm는 투과가 아니라 반사**됩니다. 이게 핵심입니다.

- **반사** 경로: 기판 표면의 요철이 파면 오차에 **2배로** 곱해져 들어갑니다.
- **투과** 경로: 굴절률 차(n−1 ≈ 0.5) 때문에 같은 요철이 절반 이하로 완화됩니다.

즉 반사로 쓰면 투과로 쓸 때보다 **4배 이상 민감**합니다. 일반 형광용 dichroic의 reflected wavefront flatness는 흔히 **5–10 λ/inch** 수준이고, 1 mm급 얇은 기판을 kinematic이 아닌 압착 방식으로 고정하면 **마운트 응력만으로 astigmatism이 수 λ** 발생합니다 — 950에서 본 1.82:1이 정확히 그 패턴입니다.

**[정량 영향]**
- FWHM 종횡비 1.14 → 1.82 (**60% 악화**)
- Halo (코어 밖 전력 비율): 600 DMSP에서 약 30–35% (실재), 950은 거의 없음
- Power density의 공간 분포가 완전히 달라짐 → **dichroic이 다르면 서로 다른 데이터셋으로 취급해야 함**

**[어떻게 알아채는가 — 비용 낮은 순서]**

1. **dichroic을 빼고 캡처** (turret 비우기 / 빈 슬롯). 스팟이 원형에 가까워지면 진단 종료. **가장 결정적인 한 장.**
2. **마운트를 풀었다 최소 토크로 재조립** → 모양이 바뀌면 응력 확정
3. **같은 dichroic을 90° 회전 재장착** → 신장 방향이 같이 돌면 dichroic 고유, 안 돌면 하류(대물렌즈/tube lens/정렬) 원인

**[해결]**
- laser-grade / imaging-flatness dichroic (reflected wavefront < λ/4 over clear aperture, **3 mm 이상 두께**)
- 또는 1064 nm 전용 dielectric mirror + 별도 경로 분리
- 마운트를 kinematic 또는 저응력 방식으로
- **당분간의 실무 지침:** dichroic별로 빔 보정을 따로 하고, 서로 다른 dichroic의 power density를 직접 비교하지 말 것

**[그림]** `fig_dichroic.png` — 코어 구조 / 반경 프로파일 / curve of growth를 두 dichroic에 대해 나란히

### P2. 화면 캡쳐 금지 — 확대 배율만큼 스케일이 틀린다 ⭐⭐ (영향 최대)

**[문제]**
ProgRes 뷰어를 **3배 확대한 상태에서 윈도우 화면 캡쳐**를 떠서 분석에 썼습니다.
분석 프로그램은 "업로드 이미지 1픽셀 = 카메라 1픽셀"을 가정하므로,

```
앱이 쓴 값:   µm/px = pitch/배율 = 6.45/60 = 0.1075 µm
실제 값:      0.1075 / 3        = 0.0358 µm
```

**[왜 놓치기 쉬운가]**
- 캡쳐한 이미지를 눈으로 보면 **아무 이상이 없습니다.** 빔은 잘 보이고, 포화도 없고, 배경도 깨끗합니다.
- 확대해서 캡쳐하는 게 오히려 "더 잘 보려고" 하는 선의의 행동입니다.
- 스케일 오류는 **결과가 그럴듯한 숫자로 나오기 때문에** 검산 없이는 절대 안 잡힙니다.

**[정량 영향 — 슬라이드 핵심 숫자]**

| 항목 | 캡쳐값 (as-is) | 정정 후 | 오차 |
|---|---|---|---|
| µm/px | 0.1075 | **0.0358** | ×3 |
| σx × σy | 1.598 × 1.394 µm | **0.533 × 0.465 µm** | ×3 |
| FWHM | 3.76 × 3.28 µm | **1.25 × 1.09 µm** | ×3 |
| 빔 면적 A_peak | 14.00 µm² | **1.556 µm²** | **×9** |
| **Power density** | (기준) | **×9** | **9배 과소평가** |

> 길이가 L배 틀리면 **면적은 L² 배**, power density는 **1/L² 배** 틀립니다.
> 3배 확대는 곧 **power density를 9배 과소평가**한다는 뜻입니다.

**[어떻게 알아채는가]**

두 가지 독립적인 방법이 있고, 둘 다 스케일바 없이 작동합니다.

1. **잡음 상관 구조** (자동 검출 가능 — 아래 P9 참조)
   화면 확대는 픽셀을 보간합니다. 원래 독립이던 잡음이 확대 배율만큼의 픽셀에 걸쳐 **상관**됩니다.
   실측: 배경 잡음의 자기상관이 1.00 → 0.70 → 0.41 → 0.11 (lag 1,2,3) — **3폭 삼각커널의 정확한 서명**.
   → 상관길이 L = 2.87 (600), 2.96 (950) → **3× 확대 확정**

2. **시야 크기 상식 검산** (손으로 할 수 있는 검산)
   프레임이 753 × 427 native px일 때
   - native = raw 카메라 px면 → 센서 상 4.86 × 2.75 mm (**정상적인 센서 크롭**)
   - native = 16× binned면 → 센서 상 77.7 × 44.1 mm (**그런 센서는 존재하지 않음**)
   → native = raw 확정

**[해결]**
- **ProgRes 자체 저장 기능으로 TIFF 저장.** 화면 캡쳐를 절대 쓰지 말 것.
- 저장된 이미지의 픽셀 크기를 **센서 네이티브 해상도와 대조**해서 1:1 확인
- 기록용으로 스케일바 있는 화면 캡쳐가 필요하면 **분석용 TIFF와 별개로 한 장 더** 찍을 것 (한 파일로 두 목적을 겸하려다 이 일이 났습니다)

### P3. 감마 / auto-contrast — 스케일보다 더 나쁘다 ⭐⭐

**[문제]**
화면 캡쳐는 **디스플레이 LUT를 거친 픽셀값**입니다. 뷰어가 감마나 auto-contrast를 적용하고 있으면 저장된 값은 CCD의 ADU에 **비선형 함수**가 씌워진 것입니다.

600 DMSP 캡쳐에서 실측: **γ ≈ 2.23** (표준 디스플레이 감마 2.2와 사실상 동일)

**[왜 이게 스케일 오류보다 나쁜가]**

| | 스케일 오류 | 감마 오류 |
|---|---|---|
| 성격 | **선형** 오차 | **비선형** 왜곡 |
| 사후 정정 | 가능 (나눠주면 됨) | **어려움** (γ와 pedestal을 모두 알아야 함) |
| 영향 범위 | 절대값만 | **빔의 형태 자체** |

감마는 어두운 값을 끌어올리므로:
- **FWHM**: γ=2.2면 캡쳐의 50% 지점은 실제로는 선형 22% 지점 → **FWHM 과대평가**
- **Halo 비율**: 어두운 날개가 부풀려짐 → **halo 과대평가**
- **D4σ, enclosed power, power density**: 전부 무의미

**[정량 영향 — 감마 되돌린 뒤 재측정]**

| | as-is (감마 씌워진 상태) | 선형화 후 |
|---|---|---|
| 600 FWHM / 회절한계 | 2.06× / 2.34× | **1.22–1.50× / 1.50–1.78×** |
| 600 halo (r≤20) | 1.52 | 1.42–1.54 → **실재하는 halo** |
| 950 FWHM / 회절한계 | 2.06× / 3.75× | **1.50× / 2.91×** |
| 950 halo (r≤20) | 1.23 | **1.01–1.10 → halo 대부분이 감마 인공물이었음** |

> ※ pedestal(흑색 오프셋)이 감마 전인지 후인지 알 수 없어 두 가정의 **범위**로 적었습니다.
> 950은 선형성 판정이 "불가"였으므로 600의 γ를 가정한 값입니다 — as-is와 선형화 값이 참값을 사이에 둡니다.

**핵심 메시지:** 950의 "halo 23%"는 **존재하지 않는 현상이었습니다.** 감마가 만든 인공물을 실제 광학 성능으로 오독할 뻔했습니다.

**[어떻게 알아채는가 — 원리가 아름다움]**

선형 검출기의 잡음은

```
Var(I) = g·I + σ_read²
```

즉 신호에 대해 **아핀이고 기울기가 양수**입니다. 따라서

> **밝기에 따라 분산이 *감소*하는 영상은 어떤 선형 검출기로도 만들어질 수 없다.**

감마 `y = I^(1/γ)`는 정확히 그 감소를 만듭니다 (멱법칙으로 보면 기울기 β = 2 − γ).
600 캡쳐 실측: 기울기 **−0.354 ± 0.086** (−4σ) → 비선형 확정, γ ≈ 2.23

**[해결]**
- 뷰어의 **gamma / contrast / brightness / auto-exposure 보정을 전부 off**
- TIFF(가능하면 16-bit)로 저장, **JPEG 절대 금지**
- 선형성을 확인하려면 **빔을 일부러 디포커스해 넓게 편 프레임**을 한 번 찍으면 됩니다 (작고 날카로운 빔은 밝기별 표본이 부족해 검증이 불가능)

**[그림]** `fig_evidence.png` 오른쪽 패널 — 원본 1:1 선형 영상은 분산이 증가, 600 캡쳐는 감소

### P4. 스케일바를 µm 스케일로 착각

**[문제]**
ProgRes 화면의 스케일바 라벨은 **`100 pxl`** — 마이크론이 아니라 **픽셀**입니다. 물리적 스케일을 전혀 주지 않습니다.

**[왜 놓치기 쉬운가]**
"스케일바가 있으니 스케일은 확보됐다"고 반사적으로 생각하게 됩니다. 현미경 이미지의 스케일바는 보통 µm이니까요.

**[역설적 교훈]**
이 스케일바는 물리 스케일은 못 주지만 **화면 확대 배율은 알려줍니다** — 바의 실측 길이가 정확히 300 PNG px이었고, 이것이 3배 확대의 첫 단서였습니다.
즉 스케일바는 **"화면 캡쳐"라는 잘못된 경로에서만 쓸모가 있던 목발**입니다. 원본 TIFF를 쓰면 애초에 필요 없습니다.

**[해결]** 물리 스케일은 스케일바가 아니라 **눈금 타깃 실측**으로 확보 (P5)

### P5. `pitch/배율`은 공칭값이다

**[문제]**
`µm/px = 카메라 픽셀 피치 / 대물렌즈 배율` 은 편리하지만 **공칭값**입니다. 다음을 전부 무시합니다:

- **Tube lens 초점거리 불일치** — 제조사마다 다릅니다: Nikon 200 mm, Olympus 180 mm, Zeiss 165 mm, Leica 200 mm.
  다른 제조사 조합이면 실효 배율이 **10–20% 틀어집니다.**
- **C-mount 중간배율 어댑터** (0.5×, 0.63×, 1× 등)
- **대물렌즈 배율 공차** (표기 60×가 정확히 60×가 아님)
- **릴레이 광학계**

**[정량 영향]** 보통 수 %, tube lens가 불일치하면 10–20%. 면적은 그 제곱이므로 **최대 40% 이상**.

**[해결]**
**눈금 타깃(stage micrometer)으로 µm/px를 한 번 실측하세요.** 같은 대물렌즈·같은 binning으로 찍어 눈금 간격을 픽셀로 재면 됩니다. 이 값 하나가 위의 모든 불확실성을 흡수합니다.

한 번만 하면 되고, 그 뒤로는 **binning이 몇이든 배율 표기가 뭐든 상관없어집니다.**

### P6. Binning을 raw 픽셀과 혼동

**[문제]**
"1 픽셀"이 raw 센서 픽셀인지 binned 픽셀인지 헷갈리면 µm/px가 binning 배수만큼 틀립니다. 2×2 binning이면 면적 4배, 4×4면 16배.

**[해결 — 확인 레시피]**
저장된 파일의 픽셀 크기를 **센서 네이티브 해상도**와 대조:

| 저장 크기 | 해석 | µm/px (6.45 µm pitch, 60×) |
|---|---|---|
| = 네이티브 | 1:1 | 0.1075 |
| = 네이티브 / 2 | 2×2 binning | 0.215 |
| = 네이티브 / 4 | 4×4 binning | 0.430 |

⚠ **ROI(부분 읽기)를 쓰면 크기는 작아지지만 피치는 그대로**입니다. Binning과 ROI를 혼동하지 마세요.
→ 캡쳐할 때 **binning 설정을 파일명이나 메모에 남기는 습관**을 들이세요.

> 참고: 6.45 µm 피치는 ICX285 계열 CCD의 값이고, 그 경우 네이티브는 1392 × 1040입니다. **카메라 데이터시트로 확인하세요.**

### P7. Peak intensity 기준의 함정 (halo가 있을 때)

**[문제]**
Gaussian fit의 peak intensity는 halo가 있으면 **계통적으로 틀립니다.**

- fit이 코어만 잡으면 → 진폭 A가 과대평가
- fit이 halo까지 잡으면 → σ가 과대평가

**어느 쪽이든 편향**이고, fit 품질(R²)만 봐서는 어느 쪽인지 알 수 없습니다.

**[정량 영향]**
600 DMSP의 경우 코어 밖에 전력의 **30–35%**가 있습니다. Peak 기준으로 계산하면 그 전력을 코어 면적으로 나누는 셈이라 **최소 1.5배 과대평가**입니다.

**[해결]**
**Curve of growth (enclosed power) 기준으로 전환하세요.**

> "반경 r 안에 들어온 실제 전력 / 그 원의 면적"

이 값은 **fit 모델에 의존하지 않습니다.** 분석 반경을 고정하고(예: r ≤ 3σ 상당) 그 안의 실측 전력으로 면적평균 밀도를 계산하면, dichroic이 바뀌어도 정의가 흔들리지 않습니다.

### P8. 잡음 정류 (noise rectification) — 가짜 halo를 만든다

**[문제]**
Halo를 재려고 "배경 위의 양수 픽셀만 더하기"를 하면, 배경 잡음의 양수 쪽만 계속 더해져 **존재하지 않는 halo가 생깁니다.**

**[정량 영향]**
**순수 Gaussian(halo 0%)을 넣었는데 7.5%의 가짜 halo가 나왔습니다.** 51,200 픽셀 규모에서는 잡음 정류가 지배합니다.

**[왜 놓치기 쉬운가]**
"음수는 물리적으로 말이 안 되니까 버리자"는 직관이 정확히 반대로 작동합니다.

**[해결]**
- **부호를 보존해서 적분하세요** (원형 조리개 안의 모든 픽셀을 배경 뺀 값 그대로 합산, 음수 포함)
- 배경은 조리개 바깥 **환형(annulus)** 에서 잡으세요
- 배경 불확실도(±1σ)가 만드는 플럭스 오차를 **같이 표시**하세요 — 이게 halo 측정의 실질적 한계를 보여줍니다

### P9. 자동화된 해결책 — 무결성 게이트 (INNO Prism v3.10)

위 P2·P3는 사람이 매번 확인하기 어렵기 때문에 **프로그램이 자동으로 잡도록** 만들었습니다.

**두 검사 모두 빔의 모양이 아니라 잡음 통계만 씁니다** — 특정 데이터에 맞춘 임시방편이 아니라 일반 검사입니다.

| 검사 | 원리 | 실측 결과 |
|---|---|---|
| **업스케일** | 배경 잡음의 2차 차분 variogram으로 상관길이 L 측정 | 600: L=2.87, 950: L=2.96 → **3× 검출** |
| **비선형성** | 분산이 밝기에 따라 감소하면 선형 검출기로 불가능 | 600: 기울기 −0.354±0.086 → **γ≈2.23 검출** |

**검증:** 합성 격자 22/22 통과, **오탐 0**. 앱 밖에서 만든 원본 1:1 선형 이미지를 대조군으로 넣어 경고가 안 뜨는 것까지 확인.

**검출 한계 (숨기지 않고 보고합니다):**

| 조건 | 결과 |
|---|---|
| γ ≳ 2.0 | 확정 검출 |
| 1 < γ ≲ 1.6 | read noise 지배와 구분 불가 → **판정 보류 또는 미탐** |
| 작고 날카로운 빔 + 업스케일 | 보간이 잡음을 뭉개 **검증 자체가 불가능** |
| bilinear + 강한 톤커브 | 배수가 ~35% 과대평가 |

마지막 항 때문에 **"L로 나누세요"라는 권고는 선형성이 확인된 경우에만** 냅니다. 아니면 권고는 "재촬영" 하나뿐입니다.

세 번째 항이 실무적으로 중요합니다:
> **화면 캡쳐는 스케일만 틀리는 게 아니라 선형성을 검증할 근거까지 없앱니다.**

**[그림]** `fig_app_warning.png` — 실제 캡쳐를 업로드했을 때 뜨는 경고 문구

## 3. 방법론 교훈 (연구실 공통으로 쓸 만한 것)

### M1. 합성 데이터로 먼저 검증하고, 실제 데이터는 나중에 본다
실제 이미지를 보면서 검출기를 튜닝하면 그 이미지에만 맞는 도구가 됩니다.
→ **합성 격자로 먼저 22/22를 통과시킨 뒤에** 실제 파일을 열었습니다.

### M2. 오탐 대조군(negative control)을 반드시 둔다
"이상을 검출했다"는 것만으로는 부족합니다. **정상 데이터에서 경고가 안 뜨는 것**을 같은 엄격함으로 확인해야 합니다.
→ 앱 밖에서 만든 원본 1:1 선형 이미지를 통과시켰습니다.

### M3. 검출 한계를 숨기지 않는다
"γ ≲ 1.6은 못 잡는다"를 문서와 코드 주석에 명시했습니다.
임의의 문턱을 세워 억지로 판정하면 **오탐이 생기고, 오탐은 신뢰를 잃게 하며, 신뢰를 잃은 경고는 무시됩니다.**

### M4. 물리 모델을 틀리게 놓으면 오탐이 난다 (실제로 겪은 실패)
처음엔 `log Var` 대 `log 신호` **멱법칙 기울기**로 선형성을 판정했는데, **선형 영상도 β ≈ 0.5~0.8로 나와 오탐**이 났습니다.
어두운 쪽에서 분산이 평평해지는 것은 비선형이 아니라 **배경 광자잡음·read noise** 때문이었고, 그건 아핀 모델의 절편이 흡수해야 할 항이었습니다.
→ `Var = g·I + σ_read²` 아핀 모델로 바꾸자 오탐이 사라졌습니다.

### M5. 단조변환 불변량과 아닌 것을 구분하라 ⭐
감마는 **단조증가 함수**입니다. 따라서:

| 결론 | 감마 영향 |
|---|---|
| 로브 개수 (bilobed vs 단일) | **불변** — 극값 개수는 단조변환에 안 변함 |
| dichroic 교체 시 모양이 바뀜 | **불변** |
| 타원율의 대소 비교 | **불변** |
| FWHM 절대값 | **영향 받음** |
| Halo 비율, D4σ/Gaussian | **영향 받음** |
| Power density | **영향 받음** |

데이터에 문제가 있어도 **어떤 결론이 살아남는지 따로 판정**할 수 있습니다. "데이터가 오염됐으니 전부 버린다"도, "일단 다 쓴다"도 틀린 대응입니다.

## 5. 아직 확정되지 않은 것 (정직하게 표시할 것)

발표에서 **추정과 확정을 구분**해 주세요.

**확정된 것:**
- 화면 캡쳐가 3× 확대본이라는 것 (스케일바 + 잡음 자기상관, 두 독립 방법이 일치)
- 600 DMSP 캡쳐에 톤커브가 씌워져 있다는 것 (분산이 밝기에 따라 유의하게 감소, −4σ)
- Dichroic 교체로 수차의 종류가 바뀐다는 것 (형태 지표는 스케일·감마 무관)

**추정 / 미확정:**
- γ의 정확한 값 (2.23은 멱법칙 가정 하의 추정치)
- Pedestal이 감마 전인지 후인지 → 선형화 결과를 범위로만 제시한 이유
- 950 DMSP의 선형성 (판정 불가 — 600의 γ를 가정함)
- **µm/px의 절대값** — 눈금 타깃 실측 전까지는 공칭값 기반 추정
- Dichroic 응력이 정확히 어떤 수차항인지 (Zernike 분해는 안 했음)

**다음 측정으로 확정할 것:**
1. ProgRes TIFF 저장으로 전환 (감마 off) → 선형성 확보
2. 눈금 타깃 µm/px 실측 1회 → 절대 스케일 확정
3. Dichroic 빼고 한 장 → 광학계 진단 확정
4. 600/950 재촬영 → halo 정량값 확정

이 네 가지는 **한 세션에 다 할 수 있습니다.**
